# Release record: v0.14.0

Compared against v0.13.0. The range is the four merges in
`v0.13.0..HEAD`. This is the release where the constitution stopped
naming the language it happened to be written in, and where the first
compiled binary appeared behind it — one script of thirty-three, the
bash original still shipped, and the port judged only against it.

## Caffeine

- **The law stopped naming the language it happened to be written
  in.** Law 1 bound "a bash script with exit-code semantics" and Law 5
  bound bash 3.2 across the whole surface, so the question raised by a
  ten-minute suite and macOS dialect pain could not be answered without
  breaking the constitution first. The boundary now binds a
  deterministic executable with exit-code semantics, and the runtime
  law is a seam: the operational core may compile, the user-editable
  side — app hooks and caffeine sidecars — stays bash 3.2 forever, and
  no interpreter runtime enters the operational path on either side
  (#116).

  evidence: the amendment shipped as a spec change validated strict before a line of Go existed, and three tests over `openspec/project.md` pin its load-bearing terms — the invariant wording, the seam and its destination, the narrowed setup claim — so the law is enforced by the suite rather than by whoever read it last; the destination it names was chosen from the previous release's measurement, where awk matched Go and Rust per-run and portability rather than speed was left as the only honest argument for compiling.

  lives in: `openspec/project.md`, `openspec/specs/guidance/spec.md`, `test/guidance_content.bats`

- **The core compiles, names the commit that built it, and its first
  port is proven against the original rather than by claim.** A new
  `core` capability says what the binary must satisfy before anything
  may lean on it: `bin/routine-selfcheck` builds it at its head and
  fails closed, so the gate only ever judges a binary built from the
  checkout under test, and a binary that cannot name the commit that
  built it is not the core. `routine-release-notes` is the first port;
  its bash implementation stays live and shipped, and the Go one is
  judged by running both over the same fixtures (#117).

  evidence: six parity comparisons run the existing bats scenarios' commands against both implementations and require byte-identical stdout with matching exit codes — the malformed-tag path diffs stderr too, strengthened after a first version passed only because both happened to exit 2 — and a seventh test asserts the build succeeded before any comparison runs; `version` must print the commit the build injected rather than `unknown`, so provenance is refusable, not decorative.

  lives in: `cmd/routine/`, `go.mod`, `bin/routine-selfcheck`, `test/core.bats`, `test/core_parity.bats`, `openspec/specs/core/spec.md`

- **A design claim about the build environment was refuted by the
  board, not by review.** The design said the runners ship Go, so the
  gate's new build step needed no CI change. The first board
  disagreed: macOS failed at `bin/routine-selfcheck: line 40: go:
  command not found`, and fail-fast cancelled ubuntu before it could
  disagree too. The workflow now installs the toolchain from `go.mod`,
  and the refuted sentence in the archived design was corrected rather
  than left to ship as a false claim (#117).

  evidence: the failing job's log names the line and the missing binary and then `routine-selfcheck: core build failed` on the next line, so the gate is measured failing closed rather than skipping; the ubuntu job's conclusion on that run is `cancelled`, not passed; the fix reads the version from `go.mod` so runner and module cannot disagree, and the following run went green on both runners.

  lives in: `.github/workflows/ci.yml`, the archived `add-go-core` design

- **The carry gate learned the difference between a loss and a
  decision.** `routine-change-check` refuses when a modified
  requirement's delta drops a live line. Its first live refusal, one
  release earlier, was right about the fact and blind to the intent:
  the delta dropped that line on purpose, and the only way past was a
  documented override run by hand. A delta now declares its deliberate
  drops in a `## Removed Lines` section, one bullet per line; the check
  exempts exactly those and still refuses every undeclared loss in the
  same run (#118).

  evidence: three new tests bring the file to eleven — two shown red against the untouched script, the third honestly labelled a characterization because a superfluous declaration passed at birth — and one of them puts a declared and an undeclared drop in the same delta, where the refusal names only the undeclared line; the check decides whether a loss was declared and never whether the removal was wise, stated in the requirement rather than discovered later.

  lives in: `bin/routine-change-check`, `openspec/specs/conventions/spec.md`

- **Two queue claims went stale the moment the corpus left the
  machine.** The queued replays of tickets 0003 and 0005 read as
  self-serve — reachable anchors, requirements on disk — and both
  prerequisites had moved out of the repository at the previous
  release's handover. The item now names what it costs: the archive
  restored into `runs/`, the app rebuilt from its patch. The tag that
  pinned the pre-rewrite chain was container-local, so a rebuilt app
  starts from the rewritten history and a restored ticket's
  `Grounded-at:` names a commit it does not contain; the anchors stay
  unedited and a replay maps its anchor by position instead (#115).

  evidence: the correction is a whole-release drift caught by re-reading the queue against the machine, not by any check — nothing in this repository decides whether a backlog claim is still true, which is the gate below.

  lives in: `BACKLOG.md`

## Gate

- **The migration is one script of thirty-three, and the half of the
  rule that removes code has never run.** The `core` capability says a
  ported script's bash implementation stays live until a separate
  change flips its gateway; no gateway has been flipped, so the
  retirement path is specified and unwalked. The one script ported is
  also the easiest kind — it reads git and prints — so nothing yet
  proves the parity oracle over a script that writes state or reads a
  fixture tree.

  evidence: `bin/` holds 33 scripts against one ported subcommand in `cmd/routine/`; the parity fixture is two empty merge commits and a tag.

  script that would decide it: the second port — a script with state — and then the first gateway flip, which is the first time parity has to hold while the bash original stops running.

- **The record survives the machine; the run evidence still does
  not.** Every render in this repository is computed from a corpus
  that git does not carry, and the corpus grew again this release.

  evidence: `git ls-files runs/` names exactly one marker file, while the live corpus holds 1,437 telemetry lines across eleven files — 305 lines more than at v0.13.0, all of them one container away from gone.

  script that would decide it: the queued release-evidence directory carrying the telemetry of the tickets that concluded in a release's window, with `routine-example` as its reader — a format with no reader is unproven.

- **The stale render shipped again, and the gap widened.**
  `evidence/retro.txt` still reports what it reported on 2026-08-14.
  The golden fixture that landed two releases ago pins the retro's
  behaviour, not the freshness of its committed render.

  evidence: the committed render reports `gate.developer runs=4 fails=2`; the live corpus reports `runs=28 fails=3`.

  script that would decide it: the queued freshness gate — the release refuses a render it did not just regenerate.

- **A change is parked mid-flight, and a second release has now
  shipped over it.** One of seventeen tasks is done on
  `add-run-timeline`; the proposal sits on main unsynced and
  unarchived, which is what a parked change should look like, and
  still nothing mechanical distinguishes parked from forgotten.

  evidence: `openspec/changes/add-run-timeline/tasks.md` carries one ticked box and sixteen open ones, unchanged across two releases; the parking note that explains it is prose in `BACKLOG.md`.

  script that would decide it: none yet, and the earning condition named last release — a second change sitting unfinished until the two become confusable — is not met; what has changed is duration, not count.

- **The backlog is the one load-bearing document nothing checks.**
  Every gate here decides something about the repository's own files;
  `BACKLOG.md` carries the standing queue, the operator's rulings and
  the case study, and its claims are checked by reading alone.

  evidence: the two replay claims corrected this release had been false since the previous release's handover, and were caught one release later by a human re-read.

  script that would decide it: none proposed — the only cheap mechanical half is a path-existence check over paths a backlog item names, which decides strictly less than the reading that caught these two.
