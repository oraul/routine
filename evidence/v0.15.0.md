# Release record: v0.15.0

Compared against v0.14.0. The range is the single merge in
`v0.14.0..HEAD`. One change, and it is the one this project had been
describing instead of fixing: a committed render that called itself a
verbatim render and had not been one since 2026-08-14.

## Caffeine

- **A defect three records described became an exit code.**
  `evidence/retro.txt` shipped stale in v0.12.0, v0.13.0 and v0.14.0.
  Each of those records named it under Gate, and naming it changed
  nothing. A render now declares its own generator in its first line,
  so `routine-render-check` re-runs that generator and compares, and
  `routine-release-check` relays the verdict the way it already relays
  the record lint (#120).

  evidence: measured on this repository before and after — `render-check: evidence/retro.txt: stale — refresh with: bin/routine-evidence > evidence/retro.txt` exit 1, then exit 0 after the refresh; the drift it caught was 47 lines once the generator's own timestamp line is excluded, `gate.developer runs=4 fails=2` against a corpus reporting `runs=28 fails=3`.

  lives in: `bin/routine-render-check`, `bin/routine-release-check`, `evidence/retro.txt`

- **The queued design was refuted before it became code.** The backlog
  had carried this as designed-and-blocked since before v0.13.0 —
  shipped unchallenged in two releases — and both halves were wrong. It was not blocked on the per-release evidence
  directory — the stale render existed already. And its mechanism could
  not work where the release actually runs: `routine-release-check` is
  the publish workflow's gate step, on a checkout where `runs/` is
  gitignored (#120).

  evidence: measured on a clean `git archive` of HEAD, which is exactly what the workflow checks out — the generator renders `routine-retro: no telemetry found under <checkout>/runs`, so the queued regenerate-and-compare would have refused every release the workflow has ever published.

  lives in: the archived `a-render-must-be-fresh` design

- **A law that forbade the gate was amended before the gate existed.**
  The `evidence` capability stated outright that freshness SHALL NOT be
  claimed mechanically, because `runs/` is absent in CI — and
  `bin/routine-evidence` said the same in its own header. Building the
  check without touching that would have shipped a script contradicting
  a live requirement. Amended, it decides freshness where the corpus is
  present and refuses to claim it where it is absent (#120).

  evidence: the delta carried the modified requirement's live lines and declared the four it drops, and the carry gate passed with no hand override — the second use of the removal grammar that landed last release, and the first that needed no override.

  lives in: `openspec/specs/evidence/spec.md`

- **The undecidable case is named rather than passed in silence, and it
  fired outside its own tests on the day it landed.** Where the
  generator reports no corpus, the check prints that it decided nothing
  and exits 0. Refusing would block every published release; passing
  quietly would report a judgment never made (#120).

  evidence: a throwaway git worktree — a corpus-less checkout nobody built for this — produced `render-check: evidence/retro.txt: not decided — the generator reports no corpus here`, exit 0, the first firing of that branch outside the suite that pins it.

  lives in: `bin/routine-render-check`, `openspec/specs/release/spec.md`

- **The telemetry globs stopped being two copies.** The corpus
  declaration needed the same file set the retro reads, and copying the
  globs would have let a render declare a corpus its body never came
  from — the exact drift class this repository keeps building gates
  against. They now have one implementation (#120).

  evidence: the retro's golden fixture is byte-unchanged through the refactor, which is the net that landed in v0.13.0 doing precisely the job it was built for; and writing the declaration exposed an imprecision before it was committed as a claim — `runs/` holds eleven files named `telemetry.jsonl` while the retro aggregates only the nine under `runs/*/tickets/`, so the header names which.

  lives in: `lib/corpus.sh`

## Gate

- **The new gate never fires where releases are published.** The
  workflow's gate step runs on a checkout with no corpus, so every
  render there is undecided. The guarantee is local to the machine the
  driver releases from. That is stated as its own requirement rather
  than a footnote, but a gate that cannot run on the authoritative path
  is weaker than its name suggests.

  evidence: measured on a clean checkout — the generator reports no corpus, so the check decides nothing; the guarantee rests on the driver running `routine-release-check` locally, which is exactly what blessed v0.14.0 with a render thirteen days stale.

  script that would decide it: none available while the corpus is untracked — the queued release-evidence directory is the only thing that would put a corpus on the publish path.

- **Harness telemetry silently disappears in a worktree.** Measured
  while probing whether delegated work could run in isolated
  worktrees: `telemetry_harness_emit` derives the app key from the
  working directory's basename and returns 0 when `runs/<key>/` does
  not exist. A worktree therefore emits nothing, so any work done there
  is invisible to the retro — and retro evidence is how this project
  earns its abstractions.

  evidence: a probe worktree ran the suite green and the gates clean and wrote not one telemetry line; the main corpus stayed at eleven files throughout.

  script that would decide it: the fix itself — derive the app key from the repository rather than the working directory, with a test that a worktree run lands in the same corpus.

- **The record survives the machine; the run evidence still does not.**
  Unchanged and now larger. Every render this release taught the gate
  to check is computed from a corpus git does not carry.

  evidence: `git ls-files runs/` names exactly one marker file, while the live corpus holds 1,623 telemetry lines across eleven files — 186 more lines than at v0.14.0.

  script that would decide it: the queued release-evidence directory with `routine-example` as its reader.

- **A change has now been parked across three releases.** One of
  seventeen tasks is done on `add-run-timeline`; the proposal sits on
  main unsynced and unarchived, and still nothing mechanical
  distinguishes parked from forgotten.

  evidence: `openspec/changes/add-run-timeline/tasks.md` carries one ticked box and sixteen open ones, unchanged since v0.13.0; the parking note is prose in `BACKLOG.md`.

  script that would decide it: none yet, and the earning condition named two releases ago — a second unfinished change making the two confusable — is still not met.

- **The migration is one script of thirty-four, and the half of the
  rule that removes code has still never run.** No gateway has been
  flipped, so the retirement path stays specified and unwalked; this
  release added a bash script rather than porting one.

  evidence: `bin/` holds 34 scripts while `cmd/routine/` exposes two subcommands, of which exactly one — `release-notes` — is a port of a bash script (`version` has no bash original); `routine-render-check` is core rather than seam, so it was written in bash only because the core still is, and it is one more script the migration owes.

  script that would decide it: the second port and then the first gateway flip, which is the first time parity must hold while the bash original stops running.

- **The backlog is the one load-bearing document nothing checks, and
  this release is the evidence.** Last release recorded that a backlog
  claim can go stale unnoticed. This one found a backlog *design* wrong
  in two independent ways, after it had shipped unchallenged in two
  releases — caught by reading it against the code, not by any check.

  evidence: the queued freshness design named a blocker that did not exist and a mechanism that could not run where the release runs; the item entered `BACKLOG.md` before v0.13.0 and is contained in the v0.13.0 and v0.14.0 tags, so it shipped twice unrefuted — a count this record first stated as three and corrected against `git tag --contains` before publishing.

  script that would decide it: none proposed — a path-existence check over paths a backlog item names is the only mechanical half available, and it would have caught neither of these.
