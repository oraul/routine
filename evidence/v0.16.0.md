# Release record: v0.16.0

Compared against v0.15.0. The range is the four merges in
`v0.15.0..HEAD`, two of them the release itself and the repair it
needed. Both exist because a rule was already written down and
nobody read it: one law that two readings got wrong the same way, and
one requirement whose second half was never built. Neither release
shipped a feature anybody asked for, and that is the honest description.

## Caffeine

- **A law that two readings got wrong the same way was underspecified,
  not unlucky.** Law 5 named the seam explicitly and still misplaced
  `bin/` twice in one day: once in the v0.15.0 record, claiming
  `routine-render-check` was "written in bash, under the seam rule",
  and once in a migration analysis that argued `bin/routine-done`
  "stays bash forever" and built a conclusion on it. The sentence
  before the seam describes the core in the same words, so "it is a
  bash script" identifies nothing and a reader reaching for the
  quickest discriminator picks language and lands wrong. A file's side
  is now decided by where it lives (#122).

  evidence: the first misreading was caught by the record lint's own spot-check before publishing and the second by the operator; the amendment appends three sentences rather than rewriting, so the three pre-existing Law 5 pins keep passing untouched, and two new pins fail on the untouched document.

  lives in: `openspec/project.md`, `openspec/specs/guidance/spec.md`

- **The road registry is judged when a release is cut.**
  `routine-render-check` emitted `harness.render` from the day it
  shipped and `lib/roads.txt` never declared it, so the registry was
  red for a full release on every machine holding a corpus. It survived
  because nothing ran the check: the telemetry capability calls it "a
  session and release-record instrument", and `routine-release-check`
  invoked it zero times. The release gate now relays it (#124).

  evidence: measured red before and green after — `undeclared road walked: harness.render` at exit 1, then `all declared roads walked or waivered (33 declared, 1 waivered)` at exit 0; the defect was found by a council seat reviewing an unrelated naming proposal, not by any gate, which is the honest account of how it surfaced. The gate's first live run then refused this very release, for the wrong reason — the entry below is that failure and its repair, and this release does not ship without it.

  lives in: `bin/routine-release-check`, `lib/roads.txt`

- **A check that cannot judge now says so instead of inventing a
  verdict.** On a corpus-less checkout — exactly what CI checks out,
  since `runs/` is gitignored — `routine-road-check` reported every
  declared road as unwalked, because it could not distinguish an absent
  corpus from one proving nothing. It now reads the corpus once and,
  where that read is empty, prints that nothing was decided and exits 0
  before computing any set (#124).

  evidence: 31 `declared road never walked` violations at exit 1 measured on a clean `git archive` of HEAD before the change, and `nothing decided — no telemetry under <dir>` at exit 0 after, while the same binary still catches the undeclared road at exit 1 on a machine holding the corpus — quieter where it cannot judge, not weaker where it can. The posture is the second use of the rule `a-render-must-be-fresh` established, not a second invention of it.

  lives in: `bin/routine-road-check`, `openspec/specs/telemetry/spec.md`

- **A gate that writes into the corpus it judges cannot judge twice.**
  The road check shipped emitting its own `harness.roads` line on the
  path where it decided nothing, so one run made the next decidable
  against a corpus holding only that footprint. Its first live run in
  the release gate refused `v0.16.0`. Three rules now take the evidence
  each needs: an undeclared road and a stale waiver are proven by a
  single observed line, while coverage waits for a run corpus, because
  "never observed" cannot be told from "never sampled here" (#126).

  evidence: the same command twice on a virgin checkout before the fix — run 1 `nothing decided` exit 0, run 2 exit 1 with 30 violations, nothing between them but run 1's own emission — and after it both runs identical at exit 0, while one appended undeclared line still exits 1 naming the road and the repo's own corpus still reports 33 declared, 1 waivered. The split is proven to match intent rather than the code by the two `release_check` tests passing with their fixtures untouched: `git diff` on that file is empty.

  lives in: `bin/routine-road-check`, `openspec/specs/telemetry/spec.md`

- **The two-agent loop ran as specified, and the delegates were the
  ones who caught the driver.** Every task in `#124` was implemented by
  a dispatched contributor while the driver held the record and re-ran
  each gate against a restored HEAD rather than trusting a report.
  Twice the driver's delegation payload instructed a contributor to
  commit and tick its own checkbox, which its contract forbids; both
  times the delegate refused and said why (#124, #122).

  evidence: three tasks, three independent red re-verifications by the driver — tests 10 and 11, then 14, 15 and 16 with all thirteen pre-existing green, then test 9 with `road-check` naming `harness.render`; one delegate caught its own false green, where a fixture tripped the gate's earlier dirty-worktree refusal so the road check never ran at all; another declined to write a test that would have duplicated a rule two existing tests own, and argued the case rather than complying.

  lives in: `.claude/agents/contributor.md`, the archived change folders

## Gate

- **The driver writes delegation payloads that violate the contract
  they delegate to.** Twice in one release the driver told a
  contributor to commit and tick its own task box. Both refusals were
  correct, which means the boundary held — but it held because the
  delegate was more careful than the instruction, and that is not a
  gate.

  evidence: two independent refusals in one day, each quoting the contract back; the queued "driver-side delegation templates" item in `BACKLOG.md` predicted this class and remains unbuilt.

  script that would decide it: a payload template with the boundary stated, or a lint over delegation prompts — the earning condition is now met twice over.

- **The command grammar was designed against the wrong source and a
  council refuted it.** An eight-kind two-level grammar was worked out
  over many turns, presented as derived, and then measured: a
  derivation rule already existed in `lib/roads.txt`, gated by
  `routine-road-check`, yielding six namespaces the proposal never
  cited. It agreed with the registry on 14 members and contradicted it
  on 12.

  evidence: four council seats reviewing independently; the law seat found the registry, the semantic seat found the `check`/`lint` boundary refuted by the scripts' own comments, the ergonomics seat found `ticket status` collides with `index.tsv`'s status column, and the migration seat found the proposal never said whether it renamed bash (1,170 occurrences across 126 files) or only Go dispatch (4 lines).

  script that would decide it: none — the registry is the derivation source, and the remaining work is to re-derive the table from it rather than to build a checker.

- **Three specification defects shipped from one driver in one change,
  and review caught none of them.** The corpus test asked for any
  telemetry where it meant ticket telemetry; the check was instructed to
  keep emitting on the path where it decided nothing; and the first
  repair collapsed three rules needing different evidence, which would
  have left the release gate blind in CI to the very defect it was built
  to catch. Each was written by the driver, validated strict, and passed
  the carry gate.

  evidence: the first two were caught by the release workflow failing on a real publish, the third by a delegate stopping at a scope boundary and reporting rather than editing another owner's fixture; none was caught by reading the proposal, and all three were in the specification rather than in the code written from it.

  script that would decide it: none — no gate here judges whether a requirement is right, only whether it is carried, validated and pinned. The nearest honest instrument is the one that worked: run it on a real machine before believing the spec.

- **The record survives the machine; the run evidence still does not.**
  Unchanged and larger again.

  evidence: `git ls-files runs/` names exactly one file, while the live corpus holds 2,190 telemetry lines across eleven files — 567 more than at v0.15.0, a figure this record first stated as 2,018 and corrected when the lint's spot-check sampled this very entry and it was re-measured rather than trusted.

  script that would decide it: the queued release-evidence directory with `routine-example` as its reader.

- **A change has now been parked across four releases.** One of
  seventeen tasks is done on `add-run-timeline`; nothing mechanical
  still distinguishes parked from forgotten.

  evidence: `openspec/changes/add-run-timeline/tasks.md` carries one ticked box and sixteen open ones, unchanged since v0.13.0.

  script that would decide it: none yet; the earning condition named three releases ago — a second unfinished change making the two confusable — is still not met.

- **The migration is one script of thirty-four and did not move.** No
  gateway has been flipped, so the retirement path stays specified and
  unwalked; this release added no port and changed two bash scripts.

  evidence: `bin/` holds 34 scripts while `cmd/routine/` exposes two subcommands, exactly one of which is a port of a bash script.

  script that would decide it: the second port, then the first gateway flip.
