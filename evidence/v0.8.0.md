# Release record: v0.8.0

Compared against v0.7.0. The range is the seven merges in `v0.7.0..HEAD`; nothing outside it is credited here. Counts come from `bin/routine-evidence` over this machine's `runs/`.

## Caffeine

- **The developer stopped re-deriving conventions someone had already established.** It now reads the briefing for the slice it implements inside, so the analyst's grounding survives the handoff instead of dying at approve.

  evidence: `briefing.md` entered the developer's closed context list (#82), and the skill's delegation payloads became literal templates naming `grounding.md`, `lint.log`, `defect.md` and `briefing.md` rather than describing them in prose (#85). Before this, the handoff named no artifact the receiver could open.

  lives in: `agents/developer.md`, `skills/routine/SKILL.md`

- **Two retry budgets stopped being adjectives and became counters.** The developer's contract used to say the loop stops after "about three" failures; a script now decides, and the same episode tracking counts defect returns.

  evidence: `episode_developer_fail_count` (consecutive, reset by a pass) and `episode_defect_count` in `lib/episode.sh`, enforced at `bin/routine-gate:140` with `[ "$_dfails" -gt 3 ]`. `agents/developer.md:86` now reads "the gate itself refuses past 3" (#84).

  lives in: `lib/episode.sh`, `bin/routine-gate`

- **A release record can now be checked for form and for one class of false claim.** Not just that it exists — that a Caffeine entry claiming knowledge was inherited names a destination that actually exists.

  evidence: `bin/routine-record-lint` refuses a missing section, a silently empty one, an entry with no `evidence:` line, and a `topic: <ns>/<name>` resolving to no `caffeine/` pair — reusing `lib/caffeine.sh` rather than growing a second resolver (#83).

  lives in: `bin/routine-record-lint`, `lib/caffeine.sh`

  topic: testing/tdd

- **The record became a release condition instead of a courtesy.** Every check around it previously fired only when the record existed, so absence passed everything routine had.

  evidence: `routine-record-lint` checks a file it is handed, and `routine-selfcheck` iterates `evidence/*.md` where a glob matching nothing iterates zero times — both correct, both vacuous on absence. After #88, `bin/routine-release-check v0.7.0` on main exits 1 with `no release record at evidence/v0.7.0.md`. The tag names the file, so a previous record cannot satisfy the next release.

  lives in: `bin/routine-release-check`, `openspec/specs/release/spec.md`

- **`ROUTINE_ROOT` now redirects the grammar lint, and the whole script surface is verified clean of the same fault.** A hardcoded root is self-concealing: the code path it breaks is the one a test needs in order to break it, which is how 26 passing tests never reached it.

  evidence: `bin/routine-spec-lint` resolves its caffeine root through `routine_root()` (#86), pinned by consequence — a fixture root resolves a topic the real corpus lacks, and refuses one only the real corpus has. Reverting the fix turns exactly those two tests red and leaves 415 green. A scan of `bin/` and `lib/` found no second instance, so the audit lint stays unearned.

  lives in: `bin/routine-spec-lint`, `lib/paths.sh`

- **The driver/delegate boundary got written down after three sessions broke it.** This one gained a contract and no capability, which is why it is the weakest entry here.

  evidence: three occurrences, two the driver's — editing a file a delegate held, a delegate running `git stash` against its own contract, and the driver committing and pushing a delegate's work mid-flight. All three share one shape: read `git status`, infer completion, act (#87).

  lives in: `CONTRIBUTING.md`, `.claude/agents/contributor.md`

## Gate

- **This record's first draft credited two earlier releases' work as this one's,** and every gate it passed said nothing.

  evidence: the draft's leading Caffeine entry cited `routine-mutation-check`, which shipped in v0.6.0, and another cited the `## Characterization:` heading, which shipped in v0.7.0. `routine-record-lint` returned ok on that draft, because it checks form and destination existence, not whether a claim belongs to the range.

  script that would decide it: a check that each entry's cited artifact appears in `git log v<prev>..HEAD`. PR #88 listed exactly this as deliberately not built, with the earning condition "earned if a record is ever found making a claim the range contradicts" — that condition has now fired, on the first record written.

- **`routine-defect` has never fired.** Across four proving runs the developer's refusal road is entirely unexercised, so its behaviour under real conditions is asserted rather than observed.

  evidence: no `spec.defective` event appears anywhere in `runs/shopapp`. Run 0003 was designed specifically to exercise it and concluded clean, which weakens the defect cap's justification rather than strengthening it — and the cap gained a counter this release (#84) that has still never been reached.

  script that would decide it: none exists. The honest next experiment is a target-side surprise — a stale `Grounded-at`, or a dependency behaving differently than the grounding recorded — not a vaguer requirement, which run 0003 showed the analyst will simply resolve.

- **The proving-run comparison spans two releases, so it cannot attribute the improvement to this one.** Runs 0001 and 0002 carried four failures each and runs 0003 and 0004 carried none, but that is a weaker claim than it looks.

  evidence: run 0002's abort was resolved by the `## Characterization:` heading, which shipped in **v0.7.0**, not here. The requirements also differed across the four runs, and no run was repeated against both the old and the new rails.

  script that would decide it: a replay harness running one fixed requirement against a pinned prior commit and against HEAD. Nothing here can do that, and it needs the target repository pinned per run as well.

- **The delegation rule added this release has no gate, only contract.**

  evidence: #87 states this in its own text — the completion signal lives in the host, outside bash, so a script inspecting the worktree sees exactly the ambiguity the rule exists to resolve.

  script that would decide it: a driver-side snapshot of git state before dispatch, compared after, catching the delegate half only. One occurrence is a fix, not a pattern; unearned until a second.

- **The caffeine deepening queue is ranking on two observations.** Both ranked topics show a 0.50 failure rate from a single failure across two runs, thin enough that one unlucky run moves the order.

  evidence: `bin/routine-evidence` reports `caffeine/ruby/rspec.sh` and `caffeine/ruby/rails.sh` at `1  0.50 ... runs=2`, both failures occurring in run 0001 and neither recurring since.

  script that would decide it: the ranking already prints run count beside the rate, so the data is present and only the reading is fragile. A minimum-observation threshold would need evidence the order actually misled someone, which has not happened.

- **The preflight gate costs 16 to 79 seconds, p50 68.** Recorded because it is the loop's dominant wall-clock cost and nothing else is within two orders of magnitude.

  evidence: `bin/routine-evidence` reports `gate.preflight runs=4 ms min=16294 p50=68293 p95=79172 max=79172`. The next slowest event, `gate.developer`, has max 209 ms.

  script that would decide it: none needed — this is a measurement, not a defect, and no requirement states a budget it could violate. It becomes a gate the day a stated budget exists.
