## Why

`runs/` is gitignored, correctly — it is per-machine mutable state. But
the consequence went unnoticed until this session made it expensive:
**no reviewer, and no council, can see that a run ever happened.**
Twelve council agents asserted "no run has been driven against a real
target" and one of those assertions reached a merged proposal, while a
complete concluded run sat in `runs/shopapp/tickets/archive/0001` — two
tasks red→green, a real block and unblock, sidecar failures then
passes, a written report.

The Laws say abstractions are earned from retro evidence. That is
unreachable when the evidence is invisible to everyone judging.

## What Changes

- **`bin/routine-evidence`** prints a committable snapshot: a header
  naming what generated it and when, then `routine-retro`'s output
  **verbatim**. It does not recompute anything — the panel's lesson is
  that a second derivation drifts, so this one calls the retro and
  relays it. A test pins the body byte-for-byte against
  `routine-retro`, making a fork impossible.
- **`evidence/retro.txt`** is committed, regenerated by that script
  (`bin/routine-evidence > evidence/retro.txt`), so a reviewer or a
  council reads measurements instead of assuming.

### The limit, stated rather than faked

CI cannot verify the snapshot is current: `runs/` is absent there, so a
regeneration in CI yields "no telemetry found". No check can prove
freshness, and pretending otherwise would be a rail that lies. What is
mechanically guaranteed is narrower and honest — the body is a verbatim
render of the retro, never hand-written, and its header says when it
was taken.
